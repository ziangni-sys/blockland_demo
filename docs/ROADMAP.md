# 路线

进度在 GitHub 的 [milestone](https://github.com/ziangni-sys/blockland_demo/milestones) 和 issue 里跟踪。每个里程碑大约是高强度使用 AI 时 2～3 天的工作量。

## 已定的前提
- 平台：先只做桌面浏览器，用 WebGPU（three.js WebGPU 渲染器）。
- 画面：像素风程序化贴图，PBR 留到画面里程碑。
- 界面：先只做中文。
- 性能目标：核显，视距 8～12 区块，60 帧。
- 发布：GitHub Pages 提供固定试玩链接。
- 联机是核心卖点（M1 试玩后确定）：架构按“联机优先”设计，开房间不需要自己架服务器。
- 不考虑向后兼容（存档、内部接口）：设计不对就一次性重构。

## 里程碑
| 里程碑 | 内容 |
|---|---|
| M1 新地基 + 结构体纵向切片 | 新架构下的世界、液体、粘连与强力胶、船、风车、转盘、推挤与携带、存档；ACCEPTANCE.md 全部通过。推迟：手机触屏、WebGL2 降级、完整生存界面、多语言。 |
| M2 联机优先 + 形状系统 | 强力胶重做与副手栏；联机地基（服务器权威，单机走同一套协议）；联机可玩（邀请链接）；方块拆成“材质 + 形状”（八分格）；凿子与半砖。M1 试玩后由负责人确定方向，细化中。 |
| M3 结构体玩法 | 机械传动（轴、齿轮）、飞艇、生存基本循环（合成、资源门槛）。原 M2，顺延。M2 试玩后细化。 |
| M4 画面与性能 | PBR 贴图管线、级联阴影、水面反射、更远视距。原 M3，顺延。 |

## 每个里程碑的完成标准
1. 有可以直接打开的试玩链接。
2. 无头测试全部通过，并有浏览器冒烟测试。
3. 对抗式审查做到某一轮不再发现中高严重度问题。
4. 新规则写进 DESIGN.md，新踩的坑写进 LESSONS.md。
5. 负责人试玩确认后，才开始下一个里程碑。

## M1 完成情况

对照完成标准：

1. **试玩链接**：有。合并到 `main` 后由 `.github/workflows/pages.yml` 发布到 GitHub Pages。
2. **测试**：1674 个无头测试，1672 个通过、2 个跳过（生成预览图的工具入口）；其中 146 个覆盖 ACCEPTANCE.md 的 24 条场景。浏览器冒烟测试 `scripts/e2e-smoke.mjs` 通过。
3. **对抗式审查**：未做到收敛。14 个模块各做了一轮（两名审查者）并修复了发现的问题，但没有再跑一轮来确认“不再发现中高严重度问题”；验收测试没有独立审计；客户端的修复没有复审。这是为了控制花费由负责人决定的。
4. **文档**：M1 新增的规则在 DESIGN.md 末尾，新踩的坑在 LESSONS.md 末尾。
5. **负责人试玩**：已确认 M1 基本完成。

与 M1 各 issue 范围的差距：

- #1：推送时跑测试的 CI 在 `.github/workflows/ci.yml`（不含计时类的性能测试，那些只在本地跑）；冒烟测试没有接进 CI。
- #5：没有“选取方块”（中键）和第三人称视角。
- #11：螺旋桨方块能放置、能随船组装，但不产生推力；没有示例风车船。

原计划推迟、实际做了的：WebGL2 降级（自动回退，地址加 `#webgl2` 可强制）、英文界面。

已知遗留：

- 把 WebGPU 的画面呈现到真实画布这一步无法在无头环境验证（软件 GPU 设备在首次呈现时丢失）。WebGPU 的着色与几何路径在离屏模式下验证过。
- 性能目标（核显 60 帧）没有在真实硬件上测量。
- 自动存档每次重新编码所有改动过的区块（约 137 个区块时有约 22 毫秒卡顿）。
- 船被挖断或炸断后仍是一个刚体，不会分裂；结构体内部没有重力更新。
